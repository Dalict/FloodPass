FloodPass

Floodgate Auto Login for AuthMe — passwordless Bedrock sign-in: Xbox-verified, automatic, zero typing

Download · Source · Issues · 简体中文文档

Official AuthMe only. FloodPass is built for the original AuthMeReloaded (5.x / 6.x). Do not install it on forks that already ship native Floodgate auto-login (such as AuthMeReReloaded) — the feature would run twice.

What It Does

Cross-play servers usually protect survival accounts with AuthMe. That works well for Java players, but Bedrock players arriving through Geyser + Floodgate have already proven who they are: they signed in with their Microsoft/Xbox account before the connection was even established. Forcing them to type a password with a gamepad keyboard adds no security and a lot of friction. FloodPass closes that gap:

  • For Bedrock players: nothing to type, ever. Registered accounts are signed in automatically about a second after joining; brand-new players are registered silently with a random password and signed in the same way
  • For Java players: zero change, they go through AuthMe exactly as before
  • Prefix-friendly: Bedrock names carrying the Floodgate prefix (for example .Steve) pass AuthMe's default allowedNicknameCharacters regex with no AuthMe config change — only genuine Floodgate UUIDs are exempt
  • Premium coexistence: a Bedrock player whose gamertag equals a premium-enrolled Java account (/premium, AuthMe 6.x + PacketEvents) joins normally while the Java account keeps its passwordless premium login
  • For server owners: one jar, no AuthMe configuration changes, one command to manage everything

How It Works

  1. A player joins; Floodgate identity data for the connection is already available at that point
  2. FloodgateApi#isFloodgatePlayer(uuid) decides whether this is a genuine Bedrock connection; Java players are never touched
  3. After a configurable delay (20 ticks by default), AuthMe has finished its own join processing and FloodPass takes over: registered players are signed in with forceLogin, unregistered players are registered with a random password via forceRegister and signed in immediately

Security basis: a Floodgate identity only exists after the Bedrock client completed Floodgate's encrypted handshake with a valid Xbox Live token. A Java Edition client cannot forge that identity, so the passwordless path is only ever offered to players Microsoft has already verified.

Requirements

  • Spigot / Paper / Purpur / Folia 1.13+ (Java 8 bytecode)
  • Floodgate 2.x (required)
  • AuthMe 5.2+, official AuthMeReloaded only (tested against 5.6.x and 6.0.x)
  • Java 8 or newer

Installation

  1. Install and configure Geyser and Floodgate (2.x) so Bedrock players can join
  2. Install the official AuthMe (AuthMeReloaded, 5.2+) and configure it as usual for your Java players
  3. Drop FloodPass-x.x.x.jar into plugins/ and restart the server

Verify with a Bedrock account: the first join should say "Registered and signed in automatically", the next join "Signed in automatically".

Commands and Permissions

  • /floodpass — show status — floodpass.admin (default OP)
  • /floodpass reload — reload config.yml and the active language file — floodpass.admin
  • Alias: /fpass

Configuration

  • language (default en) — which lang/messages_<language>.yml to use; bundled: en, zh_cn; any custom language file works too
  • enabled (default true) — master switch for automatic sign-in
  • login-delay-ticks (default 20) — ticks to wait after join; keep at 10 or above
  • auto-register.enabled (default true) — register first-time Bedrock players automatically with a random password
  • auto-register.password-length (default 32) — random password length (8-64); Bedrock players never need to know it
  • bypass-nickname-check (default true) — re-allow Bedrock players denied by AuthMe's allowedNicknameCharacters; only genuine Floodgate UUIDs are exempt
  • premium-conflict-guard (default true) — keep Bedrock players joinable when their gamertag equals a premium-enrolled Java account
  • debug (default false) — console logging of every sign-in decision

Known Limitations

  • Bedrock accounts are stored under their Floodgate-prefixed name; changing the Floodgate username prefix later breaks the name mapping and requires an AuthMe database migration
  • forceLogin bypasses AuthMe two-factor authentication for Bedrock accounts — intended for Xbox-verified identities
  • On AuthMe 6.x with the experimental dialog login UI (Minecraft 1.21.6+), the login dialog may flash briefly before the delayed auto sign-in completes
  • AuthMe's /premium command targets Java accounts and is safely rejected for regular Bedrock players — they do not need it, FloodPass already signs them in
